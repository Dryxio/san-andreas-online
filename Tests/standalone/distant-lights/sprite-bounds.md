# Distant corona screen rejection

`clang++ -std=c++17 -O2 -I Shared/sdk Tests/standalone/distant-lights/sprite-bounds.cpp -o /tmp/neon-sprite-bounds && /tmp/neon-sprite-bounds`

The test compares the early rejection with the four corners generated by GTA's
`CSprite::RenderBufferedOneXLUSprite_Rotate_Aspect` at angle zero. It checks
300,000 deterministic cases over three viewport sizes, negative/zero extents,
and exact or adjacent floating-point screen edges. Touching an edge stays in.

The renderer uses the active raster for projection but RsGlobal dimensions for
this rejection, matching the native sprite function. Fog stretches the vertical
extent before rejection. Texture changes for invisible sprites can therefore
be skipped along with the native trigonometry. Visible sprites retain GTA's
buffered renderer, order, blend mode and texture.

This test proves the screen predicate, not FPS improvement or general GPU
compatibility. Runtime comparisons must include same-launch controls and visual
checks; do not interpret FPS differences between VM launches as causal gains.
